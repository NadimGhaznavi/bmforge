Оновлюйте `CHANGELOG.md` під час щоденної розробки функцій, виправлення помилок, обслуговування та роботи з документацією. Записуйте суттєві результати після завершення роботи, поки зрозумілі її мета й наслідки.

## Місце в процесі

| Етап | Відповідальність | Процес |
| --- | --- | --- |
| Створення проєкту | Створити журнал змін і заголовок `Unreleased` | [Налаштування випусків]({{ site.baseurl }}{% link uk/pages/release-setup.md %}) |
| Розробка й обслуговування | Записувати завершені зміни під `Unreleased` | Цей процес |
| Випуск | Призначити версію й час через скрипт випуску | [Створення випуску]({{ site.baseurl }}{% link uk/pages/creating-a-release.md %}) |

## Запис змін

1. Перегляньте завершену роботу й визначте, що змінилося для користувачів, операторів або розробників, які обслуговують проєкт.
2. Додайте або оновіть стислий запис під наявним заголовком `## [Unreleased]`. Зберігайте рівно один такий заголовок із зазначеним написанням.
3. Об’єднуйте пов’язані деталі в чіткий результат. Використовуйте розділи `Added`, `Changed`, `Fixed` або `Removed`, коли вони допомагають упорядкувати записи; порожні розділи пропускайте.
4. Комітьте оновлення журналу змін разом із відповідними змінами.

Описуйте реалізовану поведінку та її практичний ефект. Включайте суттєві зміни встановлення, конфігурації, сумісності, надійності та документації. Не перераховуйте кожен редагований файл, проміжні спроби чи рутинні зміни без суттєвого впливу.

## Підсумок великих змін

Якщо завдання охоплює багато дрібних змін, додайте або оновіть `### Summary` безпосередньо під `## [Unreleased]`. Поясніть проблему та рішення одним-двома реченнями. Залишайте додаткові пункти лише там, де вони корисні, і не видаляйте записи інших невипущених змін.

```markdown
## [Unreleased]

### Summary

The event log flickered during refresh. It now keeps existing entries visible as new events arrive.

### Fixed

- Preserve the selected event and scroll position during refresh.
```

## Передавання скрипту випуску

Зберігайте записи опублікованих випусків, а нову роботу записуйте під `Unreleased`. Під час звичайної розробки версії, час випуску та кодові назви призначає процес випуску.

Скрипт вставляє заголовок із версією й часовою позначкою безпосередньо під `## [Unreleased]`. Накопичені записи входять до цього випуску, а `Unreleased` лишається порожнім для наступних змін. Коли робота готова до публікації, дотримуйтеся [Створення випуску]({{ site.baseurl }}{% link uk/pages/creating-a-release.md %}).

Перед завершенням завдання перевірте відповідність запису фактичному результату, об’єднання споріднених записів і збереження історії випусків та ще не опублікованої роботи.
