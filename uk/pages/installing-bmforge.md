BMForge розгортає свій інструментарій вихідного коду, документацію та метадані CMDB у `/opt/prod/bmforge`. Він не має прикладної служби, бази даних чи запланованого завдання для створення. Сайт документації публікується окремо через [GitHub Pages]({{ site.baseurl }}{% link uk/pages/github-pages-publishing.md %}).

## Підготовка робочої копії

Використовуйте Linux із Bash і Python 3.10 або новішим. Запускайте з окремої робочої копії BMForge потрібного випуску, наприклад `/opt/dev/bmforge`. Скрипти самі визначають її шлях і можуть запускатися з іншого каталогу. Перегляньте випуск і відокремлюйте локальні зміни від версії розгортання.

Перегляньте допомогу чи перевірте файлове розгортання без змін:

```sh
scripts/install.sh --help
scripts/install.sh --check
```

Наявний `/opt/prod/bmforge` без маніфесту власності не приймається автоматично під керування інсталятора. Перевірте й узгодьте цей каталог до встановлення.

## Встановлення та оновлення

Перше встановлення:

```sh
sudo scripts/install.sh
```

Оновлення наявного встановлення:

```sh
scripts/upgrade.sh --check
sudo scripts/upgrade.sh
```

Встановлення можна повторювати. Оновлення потребує наявного керованого встановлення. Обидві операції копіюють дерева `bmforge/`, `scripts/`, `templates/` і `pages/`, а також кореневі index, README, журнал змін, ліцензію, конфігурацію Jekyll і файл домену. Історія Git, тести, кеші й скомпільований байткод не розгортаються. Застарілі керовані файли видаляються; чужі файли зберігаються. Новий вихідний файл, який перезаписав би чужий файл призначення, відхиляється.

Установлені константи: `/opt/prod/bmforge/bmforge/constants/DBMForge.py`. Перевірте їх:

```sh
python3 -B scripts/check-cmdb.py --name BMForge --root /opt/prod/bmforge bmforge/constants/DBMForge.py
```

Зареєструйте `BMForge` у CMDB і проскануйте застосунки для підтвердження виявлення. Сама локальна перевірка не доводить доступність для віддаленої інвентаризації.

## Видалення

З окремої робочої копії:

```sh
scripts/uninstall.sh --check
sudo scripts/uninstall.sh
```

Видалення прибирає керовані файли з маніфесту й маркер успішної версії, після чого видаляє порожні керовані каталоги. Чужі файли й каталоги залишаються разом із порожнім записом власності, якщо стан зберігається. Це дозволяє повторне видалення й перевстановлення без привласнення стороннього каталогу. Вихідна робоча копія й сайт GitHub Pages не змінюються; команда видаляє лише локальне встановлення.

Якщо розгортання завершилося збоєм, скрипт повідомляє помилку. Він не відкочує вже скопійовані файли. Перевірте встановлення перед повтором; маніфест власності враховує часткові копії, а `.deployment-version` записує останнє завершене розгортання, якщо воно було.
