# Константи

**Ідентифікатор компонента:** `{{ page.component_id }}` · **Специфікація:** `{{ page.spec_version }}` ({{ page.spec_status }})

## Призначення

Уникайте **магічних рядків і значущих числових літералів** уже з першого модуля застосунку. Групуйте значення за **семантичною предметною областю**, а не в загальні купи полів, стандартних значень і підписів. Це стандарт кодування, а не нова бібліотека виконання, служба, метаклас чи фреймворк. Кожен новий застосунок BMForge отримує цю навичку в базовому наборі.

## Схвалені модулі виконання

| Походження | Модуль | Дозволене використання |
| --- | --- | --- |
| Стандартна бібліотека Python | `typing` | `Final` для документування фіксованих значень, шляхів, портів, констант структури та задумано незмінних значень за замовчуванням |
| Стандартна бібліотека Python | `enum` | `StrEnum` і `IntEnum` для закритих словників протоколів, дій і станів |

Використовуйте лише потрібне вибраній групі констант. `Final` виражає намір для перевірок типів, але **не гарантує незмінності під час виконання**. Не додавайте власний метаклас `ConstGroup`, реєстр, глобальний кеш налаштувань чи сторонній конфігураційний фреймворк без дозволу користувача.

## Іменування та власність

- Зберігайте класи у `<app>/constants/D<Name>.py`: одна змістовна предметна група в модулі. Використовуйте назви на кшталт `DProject`, `DNetwork`, `DZMQ`, `DField`, `DSQL`, `DGameDef`, `DStatus`. Віддавайте перевагу великим літерам в атрибутах, відповідності назв модуля й класу та явним імпортам із модуля-власника.
- Визначайте ідентичність застосунку та буквальний `VERSION`, метадані CMDB, шляхи розгорнутих компонентів і декларації мережевих слухачів у `D<Project>` (почніть із `templates/project/constants/DProject.py`). Версія має бути буквальною, щоб інструменти випуску могли прочитати її без виконання коду.
- Використовуйте `Final` для фіксованих конфігураційних ключів, полів повідомлень протоколу, ідентифікаторів дій, семантичних значень за замовчуванням, портів, тайм-аутів, шляхів і відповідностей SQL-стовпців. Використовуйте `StrEnum` для закритих текстових словників, а `IntEnum` — для стабільних числових кодів; зберігайте зовнішні серіалізовані значення.
- Тримайте визначення класів зрозумілими й лише з даними. Не читайте файли середовища, не виконуйте ввід/вивід і не звертайтеся до зовнішніх служб просто під час імпорту модуля констант.
- Централізуйте визначення **один раз** у межах предметної області. Використовуйте посилання на іменовані значення там, де вони покращують зрозумілість, але уникайте циклічних імпортів і непрозорих псевдонімів. Не створюйте окремі `DField`, `DLabel` і `DDefault` для кожної функції автоматично.
- **Не** замінюйте навмисні поля схеми, API-ключі, коди станів, мережеві методи чи назви конфігурації перекладеними значеннями. Вони мають бути стабільними між мовами та зберігатися як канонічні ідентифікатори.

Приклад:

```python
from enum import StrEnum
from typing import Final

class DNetwork:
    HTTP_PORT: Final[int] = 49700
    CONFIG_FILE: Final[str] = "conf/app.json"

class DStatus(StrEnum):
    RUNNING = "running"
    PAUSED = "paused"
```

## Межа з локалізацією

Видимий користувачеві підпис **не є** константою протоколу. Використовуйте стабільний ключ повідомлення `DText` і отримуйте локалізоване значення через [Локалізацію застосунків]({{ site.baseurl }}{% link pages/component-localization.md %}). Наприклад, `DStatus.RUNNING` залишається `"running"` у MariaDB/JSON, тоді як `localizer.text(DText.STATUS_RUNNING, locale=language)` повертає читабельний підпис потрібною мовою. Не розміщуйте англомовні константи `*_LABEL` в активностях, інтерфейсах або компонентах відображення.

Звичайні SQL-запити, тимчасові локальні змінні, MIME-типи, очевидний одноразовий текст інтерфейсу та несемантичні числа не потребують кожне окремої константи. Насамперед усувайте повторювані або значущі для поведінки літерали, а не замінюйте все непрямими посиланнями. Перевизначення під час виконання належать процесу [Конфігурації виконання]({{ site.baseurl }}{% link pages/runtime-configuration.md %}); стандартні значення констант не є остаточною конфігурацією розгортання.

## Критерії приймання

1. Значущі рядкові й числові літерали містяться у предметних групах або явно вибраних стандартних переліках; не повинно бути розкиданих повторів методів повідомлень, ключів схем, статусів чи магічних портів.
2. Загальна ідентичність застосунку й версія є буквальними, стабільними й доступними для виявлення; мережеві й постійні декларації CMDB відповідають розгортанню.
3. Модулі `D` не імпортують предметні активності та не мають побічних ефектів. Немає власного фреймворка констант чи несхвалених залежностей.
4. Зміна константи зберігає сумісність із мережею та сховищем, якщо явну міграцію не погоджено.
5. Ключі перекладу — стабільні значення `StrEnum`; текст інтерфейсу береться з мовних каталогів, а не з англомовних констант.
