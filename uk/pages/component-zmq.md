# Сервер запитів/відповідей ZeroMQ

**Ідентифікатор компонента:** `{{ page.component_id }}` · **Специфікація:** `{{ page.spec_version }}` ({{ page.spec_status }})

Цей контракт дотримується [інженерної політики]({{ site.baseurl }}{% link uk/pages/engineering-contract.md %}), [контракту перевірок працездатності]({{ site.baseurl }}{% link uk/pages/health-checks.md %}) і [правил простежуваності]({{ site.baseurl }}{% link uk/pages/specification-lifecycle.md %}).

## Призначення та обсяг

Реалізуйте локальний слухач запитів/відповідей `pyzmq` для невеликих керуючих і пошукових повідомлень JSON. Ця специфікація охоплює **лише REQ/REP**. Не замінюйте непомітно на PUB/SUB, PUSH/PULL, черги чи розподілені брокери. Інший транспорт слід специфікувати окремо за вимогою застосунку.

## Схвалені модулі виконання

Це **повний перелік схвалених модулів інфраструктури повторно використовуваного сервера ZeroMQ REQ/REP** у специфікації `0.3.1`.

| Походження | Модуль | Призначення |
| --- | --- | --- |
| Стандартна бібліотека Python | `collections.abc` | Інтерфейс обробника `Callable` |
| Стандартна бібліотека Python | `dataclasses` | `dataclass` і `field` для оболонки повідомлення |
| Стандартна бібліотека Python | `json` | Кодування й декодування версійного вмісту повідомлень |
| Стандартна бібліотека Python | `threading` | `Thread` і `Event` для життєвого циклу потоку-власника сокета |
| Стандартна бібліотека Python | `typing` | Анотація `Any` в оболонці |
| Сторонній | `zmq` | Контекст PyZMQ, REP-сокет, опитування, тайм-аути й очищення |

**Межа схвалення:** цей список обов’язковий для повторно використовуваної інфраструктури компонента. Codex може змінювати назви локальних класів, налаштовувати порти та шляхи й реалізовувати обробники застосунку, але **повинен зупинитися й запитати користувача** перед додаванням, видаленням або заміною схваленого модуля чи фреймворка. Не встановлюйте інший пакет як обхід. Схвалені зміни належать до нової специфікації BMForge до її впровадження.

Це модулі імпорту Python, а не повне дерево транзитивних залежностей. Версії встановлених пакетів фіксує файл залежностей застосунку. Предметна логіка та інші вибрані компоненти BMForge не входять до списку й не можуть непомітно змінювати технології транспорту.

**Не входять до цього компонента:** `pymysql`, клас BMGeoIP `GeoIpLookup` і спеціалізована поведінка `LookupHandler` у знімку належать до прикладної інтеграції, а не є додатковими схваленими модулями транспорту. Не підмінюйте реалізацію asyncio, брокером, власним сокетним протоколом чи іншим шаблоном ZeroMQ. Інший транспортний шаблон потребує окремої схваленої специфікації.

## Обов’язковий контракт

- Реалізуйте сервер із конфігурованою адресою `tcp://host:port`, використовуючи мережеві налаштування застосунку. Оголосіть слухача за правилами мережевої конфігурації BMForge та CMDB; не відкривайте слухача поза довіреною мережею без явного перегляду вимог безпеки.
- Робочий потік створює, володіє, використовує й закриває власний контекст ZeroMQ і REP-сокет **в одному потоці**. Використовуйте обмежений інтервал опитування, тайм-аут надсилання та `LINGER=0`; не діліться сокетами між потоками.
- Синхронно повідомляйте батьківському процесу про помилку прив’язування/ініціалізації до оголошення готовності. Пізніші фатальні збої робочого потоку мають виявлятися явною перевіркою або рівнозначною інтеграцією з наглядовим процесом.
- Приймайте рівно один JSON-фрейм на запит і надсилайте рівно одну відповідь на кожен отриманий запит, включно з некоректними, зберігаючи чергування REQ/REP. Визначайте безпечну поведінку для неправильних фреймів і винятків обробника; один поганий запит не повинен непомітно вбивати робочий потік.
- Версійна оболонка UTF-8 JSON містить `protocol_version` (ціле число), `sender` (непорожній рядок), `target` (рядок або null), `method` (непорожній рядок) і `payload` (об’єкт). Відхиляйте несумісні версії чи форми. Обмежуйте розмір повідомлень відповідно до моделі загроз застосунку.
- **Відхиляйте недійсні скалярні значення Unicode до передавання в прикладний обробник.** JSON-екранування `\u` може декодуватися в одиночні сурогати UTF-16, навіть якщо фрейм передано коректним UTF-8. Перевіряйте всі декодовані рядки та ключі об’єктів, включно з вкладеними payload і кореляційними полями оболонки. Відповідайте `invalid_request` і залишайте слухач працездатним. Коректні екрановані *пари сурогатів*, які позначають символи Unicode, дозволені. Недійсний зовнішній Unicode не можна класифікувати як фатальний дефект застосунку.
- Відповіді зберігають кореляційний контекст запиту, якщо він доступний. Визначайте успішний `status: ok` і помилковий `status: error` зі структурованими `error.code` та `error.message`. Обробники застосунку визначають допустимі методи, перевірку аргументів, авторизацію за потреби та бізнес-операції.
- При зупинці служби швидко завершуйте роботу, звільняйте порт і повідомляйте про фатальні помилки. Клієнтам потрібен тайм-аут приймання й визначена політика повтору/перепідключення, бо після невдалого REQ-обміну може знадобитися створення нового REQ-сокета.
- Зарезервуйте `method: "health"` із порожнім об’єктом payload на наявній точці REQ/REP. Працездатний слухач/обробник повертає звичайну оболонку зі `status: "ok"`; недоступний слухач має завершувати обмежений клієнтський виклик помилкою. Не додавайте HTTP-сервер, фоновий наглядач або автоматичне відновлення лише для моніторингу. HTTP `/health` застосунку може викликати цей метод і передавати стан ZeroMQ у CMDB.
- Не додавайте універсальний диспетчер, службу виявлення, шар збереження чи асинхронний брокер без вимоги.

## Критерії приймання

1. Запуск на тимчасовому loopback-порту; клієнт обмінюється правильною оболонкою запиту й відповіді, включно з полями протоколу та маршрутизації.
2. Некоректний JSON, багатофреймове повідомлення, непідтримувана версія протоколу, неправильний target і невідомий метод повертають визначені помилки; робочий потік після цього працює.
3. Синтаксично коректний JSON з екранованими одиночними `\ud800` / `\udfff` в рядках оболонки, вкладених значеннях payload чи ключах об’єктів призводить до `invalid_request`. Наступний правильний запит успішний **на тому самому сервері**; правильний Unicode, включно з парами сурогатів, приймається.
4. Виняток обробника обробляється за задокументованою політикою, без тихого зависання.
5. Конфлікт прив’язування повідомляється під час запуску; примусовий збій робочого потоку помітний наглядачеві.
6. Завершення звільняє сокети й потоки; перевірено тайм-аут і відновлення клієнта.
7. Запит `health` отримує звичайну успішну відповідь, поки обробник працює; зупинений слухач завершується тайм-аутом/помилкою у визначених межах і не може вважатися здоровим застосунком.
8. Прикладний код не імпортує bmgeoip чи BMForge під час виконання; методи повідомлень і схеми payload документуються локально.
9. Транспорт ZeroMQ використовує лише схвалені модулі; будь-які заміни або додавання були схвалені користувачем до реалізації.
