# HTTP-сервер відображення

**Ідентифікатор компонента:** `{{ page.component_id }}` · **Специфікація:** `{{ page.spec_version }}` ({{ page.spec_status }})

Цей контракт дотримується [інженерної політики]({{ site.baseurl }}{% link uk/pages/engineering-contract.md %}), [контракту перевірок працездатності]({{ site.baseurl }}{% link uk/pages/health-checks.md %}) і [правил простежуваності]({{ site.baseurl }}{% link uk/pages/specification-lifecycle.md %}).

## Призначення та обсяг

Надайте невелику HTTP-службу, якою володіє застосунок, використовуючи Python `ThreadingHTTPServer`, `BaseHTTPRequestHandler` і, якщо потрібен HTML, шаблони Jinja2 з автоматичним екрануванням. Не вводьте Flask, FastAPI, збірку фронтенду, фреймворк автентифікації чи додаткову інфраструктуру без вимоги споживача.

## Схвалені модулі виконання

Це **повний список схвалених модулів повторно використовуваної інфраструктури HTTP-сервера відображення** у специфікації `0.3.0`.

| Походження | Модуль | Призначення |
| --- | --- | --- |
| Стандартна бібліотека Python | `argparse` | Аргументи хоста й порту CLI |
| Стандартна бібліотека Python | `http.server` | `ThreadingHTTPServer`, `BaseHTTPRequestHandler` і життєвий цикл HTTP |
| Стандартна бібліотека Python | `ipaddress` | Перевірка адреси IPv4 для прив’язування |
| Стандартна бібліотека Python | `json` | JSON-запити й відповідь `/health` |
| Стандартна бібліотека Python | `logging` | Діагностика помилок запитів і життєвого циклу |
| Стандартна бібліотека Python | `pathlib` | Визначення шляхів шаблонів і статичних ресурсів |
| Стандартна бібліотека Python | `signal` | Завершення роботи за SIGTERM |
| Стандартна бібліотека Python | `urllib.parse` | Розбір URL і параметрів запиту |
| Сторонній | `jinja2` | `Environment`, `FileSystemLoader`, `StrictUndefined`, `select_autoescape` для серверного HTML |

**Межа схвалення:** список обов’язковий для повторно використовуваної інфраструктури компонента. Codex може перейменовувати локальні класи, налаштовувати порти й шляхи та реалізовувати обробники застосунку, але **має зупинитися й запитати користувача** до додавання, видалення або заміни схваленого модуля чи фреймворка. Не встановлюйте інший пакет як обхідний шлях. Схвалені користувачем зміни мають бути включені до нової специфікації BMForge перед використанням.

Це модулі імпорту Python, а не повне дерево транзитивних залежностей. Файл залежностей застосунку-споживача містить версії встановлених пакетів. Предметна логіка та окремо вибрані компоненти BMForge не входять до списку й не повинні непомітно змінювати технології цього компонента.

**Не входять до цього компонента:** імпорти PyMySQL в обробнику HTTP BMGeoIP належать до операцій із базою даних застосунку GeoIP, а не до HTTP-транспорту. Plotly.js, Leaflet і Cytoscape.js — *необов’язкові можливості браузерного відображення*, описані окремо у [Візуалізаціях]({{ site.baseurl }}{% link pages/component-visualization.md %}), а не неявні залежності HTTP. Вибирайте лише потрібні застосунку. Не замінюйте реалізацію на Django, Flask, FastAPI, Werkzeug, Gunicorn, NGINX чи інший серверний фреймворк без схвалення користувача.

## Еталонний знімок

- `components/reference/bmgeoip/bmgeoip/server/BMGeoIPServer.py`: слухач, прив’язування CLI, інтеграція, життєвий цикл.
- `components/reference/bmgeoip/bmgeoip/server/BMGeoIPHandler.py`: маршрути GET/HEAD/POST, шаблони, JSON-відповіді й точки стану.

Вони містять маршрути, завантажувачі даних, глобальні значення й файли, специфічні для GeoIP. **Не відтворюйте цю поведінку** у сторонніх застосунках.

## Обов’язковий контракт

- Застосунок надає клас/точку входу сервера, обробник запитів, маршрути та залежності служб.
- Читайте стандартні параметри слухача з мережевих констант застосунку й робочих перевизначень; за потреби дозволяйте явні перевизначення CLI. Перевіряйте хост і порт перед прив’язуванням. Оголошуйте слухача у `CMDB_NETWORK` і дотримуйтеся процесу мережевої конфігурації.
- Використовуйте обмежений тайм-аут сокета запиту. Помилка прив’язування та фатальний збій робочого потоку мають проявлятися як помилки; не оголошуйте готовність до успішного прив’язування.
- Реалізуйте `GET`, `HEAD` і лише потрібні методи змін. Запит HEAD надсилає заголовки без тіла. Невідомі маршрути повертають 404.
- Повертайте правильні коди статусу, `Content-Type`, UTF-8 де потрібно, `Content-Length`, `Cache-Control: no-store` за необхідності та `X-Content-Type-Options: nosniff`.
- Для JSON-записів перевіряйте метод, шлях, Content-Type, розмір запиту, схему та поля користувача; відхиляйте некоректні чи завеликі запити кодами 4xx, а не неконтрольованими винятками. Враховуйте правила джерела й доступу до точок, що змінюють стан; перевірка того самого походження не є автентифікацією.
- Використовуйте автоматичне екранування HTML Jinja2 й помилку на відсутні значення шаблону; шаблони, статичні ресурси й дані маршрутів належать застосунку. Не вставляйте секрети до HTML або публічної діагностики.
- Надавайте `GET /health` на наявному HTTP-слухачі як перевірку для CMDB: `200`, якщо необхідні компоненти працездатні, `503`, якщо потрібний компонент недоступний. Повертайте невеликий JSON станів із контракту перевірок працездатності. Постійний `200` лише тому, що процес працює, недостатній. Не додавайте окрему реалізацію `/ready` без конкретної вимоги.
- Коректно закривайте HTTP-слухача та власні фонові потоки при завершенні, включно з SIGTERM. Не залишайте осиротілих потоків.
- Тримайте предметну логіку застосунку поза загальною механікою HTTP. За потреби використовуйте типізовані інтерфейси або передані залежності без вигадування додаткових рівнів.

## Критерії приймання

1. Прив’язування до тестової loopback-адреси й тимчасового порту; GET для відомого маршруту повертає правильне тіло, тип і довжину, HEAD не повертає тіла.
2. Невідомий маршрут повертає 404; непідтримуваний метод змін або некоректний/завеликий JSON не зупиняє сервер.
3. Значення користувача в HTML екрануються; статичні ресурси не можуть виходити поза дозволені шляхи.
4. `GET /health` повертає `200` і стани компонентів, коли вони працездатні; змодельований збій ZeroMQ чи БД застосунку повертає `503` із назвою компонента. Немає прямого запиту CMDB до БД або нового HTTP-слухача.
5. Перевірено зайняту адресу, недійсний порт і коректне завершення; не залишається робочих потоків.
6. Установлений застосунок використовує задекларовані адресу/порт, поважає робочі перевизначення й не імпортує BMForge/bmgeoip під час виконання.
7. HTTP-реалізація використовує лише схвалені модулі; будь-яку заміну чи додавання користувач схвалив до реалізації.
