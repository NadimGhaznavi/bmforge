# GIF-анімація

**Ідентифікатор компонента:** `{{ page.component_id }}` · **Специфікація:** `{{ page.spec_version }}` ({{ page.spec_status }})

Цей необов’язковий компонент кодує послідовність **уже створених зображень Pillow** в анімований GIF. Застосунок-споживач відповідає за вміст кадрів і частоту, незалежно від того, чи це графіки, знімки екрана, симуляції Snake або фотографії. Кодувальник відповідає за знімки кадрів, розміри, квантування часу, палітри, метадані повторення й кодування GIF. Він **не** візуалізує предметні дані, не робить знімків екрана, не керує камерою, не планує завдань, не публікує файлів, не запускає HTTP-служби й не кешує медіа.

Скопіюйте [автономний шаблон GIFAnimation]({{ '/components/templates/gif-animation/interface/GIFAnimation.py' | relative_url }}) до пакета `interface/` застосунку-споживача. Імпорти BMForge під час виконання відсутні. Дивіться [інженерний контракт]({{ site.baseurl }}{% link uk/pages/engineering-contract.md %}), [класифікацію класів]({{ site.baseurl }}{% link uk/pages/classification.md %}) і [простежуваність специфікацій]({{ site.baseurl }}{% link uk/pages/specification-lifecycle.md %}). Компонент відокремлений від [браузерної візуалізації]({{ site.baseurl }}{% link uk/pages/component-visualization.md %}): Plotly.js не кодує GIF.

## Схвалені модулі виконання

| Походження | Модуль | Призначення |
| --- | --- | --- |
| Стандартна бібліотека Python | `io` | Створення GIF у пам’яті через `BytesIO` |
| Стандартна бібліотека Python | `pathlib` | Запис у шлях, переданий застосунком |
| Сторонній | `PIL.Image` (**Pillow 12.3.0**) | Знімки зображень, композиція прозорості та кодування GIF |

Це повний перелік модулів реалізації GIF-кодувальника. **Активність генерації кадрів** у застосунку може мати власні окремо схвалені залежності. Не додавайте ImageMagick, FFmpeg, moviepy, пакети захоплення браузера чи інший кодувальник без схвалення власника й нової версії специфікації. Не змінюйте бекенд Pillow і не замінюйте непомітно потрібну версію. Якщо цих модулів недостатньо, зупиніться й запитайте користувача.

## Контракт

1. `GIFAnimation(width, height, loop=True, background=(255, 255, 255))` володіє окремою анімацією. Розміри — додатні цілі числа, `loop` — булеве значення, `background` — RGB-кортеж байтових значень.
2. `add_frame(image, duration_ms=...)` зберігає знімок Pillow `Image.Image` **точно** заданих розмірів. Ніколи не змінює розмір, не обрізає й не мутує кадр викликача. Тривалість — ціле число від **10 до 600000 мс**.
3. Тривалості округлюються до **10-мілісекундних** кроків формату GIF на основі **накопиченого часу**, а не кожного кадру окремо. Для трьох кадрів по 75 мс затримки становлять 80, 70 і 80 мс. Невелике відхилення кадрів не накопичується. Pillow може об’єднувати однакові сусідні зображення зі збереженням сумарної тривалості.
4. Повнокадрове відтворення використовує метод видалення **2** (відновлення фону перед наступним кадром); `loop=True` записує метадані безкінечного повторення GIF (`loop=0`), а `loop=False` їх пропускає.
5. Уже індексовані кадри `P` **без прозорості** зберігають палітри; це підтримує фіксовані палітри графіків, вибрані застосунком. Інші режими, включно з RGBA і прозорими індексованими зображеннями, компонуються на `background` та кодуються як непрозорі RGB. GIF не зберігає часткову альфу. Для графіків із важливими кольорами створюйте кадри зі спільною палітрою `P`; для фотографій можна використовувати квантування Pillow.
6. `to_bytes()` повертає повністю закодований GIF для відповіді застосунку чи його атомарного шару збереження. `save(path)` записує GIF в наявний батьківський каталог і повертає `Path`. Порожня анімація або недійсний кадр спричиняє змістовний виняток, а не порожній GIF чи вигаданий результат.
7. Кадри зберігаються в пам’яті. Контракт розрахований на обмежені послідовності, як короткі демонстрації й вибрані таймлапси, а не живе відео чи необмежене захоплення. Застосунок сам керує зберіганням, власністю файлів, атомарною публікацією, запитами та моніторингом.

## Приклад

```python
from PIL import Image
from yourapp.interface.GIFAnimation import GIFAnimation

animation = GIFAnimation(800, 450, loop=True, background=(16, 23, 32))
for frame_path in frame_paths:                  # Ordered by the application
    with Image.open(frame_path) as frame:
        animation.add_frame(frame, duration_ms=75)

gif_data = animation.to_bytes()                 # HTTP/storage integration owns delivery
animation.save("output.gif")                   # Or write a GIF to an existing directory
```

Кадри також можна створювати повністю в пам’яті й передавати напряму. Активність застосунку повинна впорядковувати кадри, малювати накладення та вибирати час; не переносіть предметну логіку до `GIFAnimation`.

## Код, походження та передавання

- **Шаблон, яким володіє застосунок:** `components/templates/gif-animation/interface/GIFAnimation.py`. Це канонічна реалізація для копіювання й адаптації.
- **Незмінний еталон:** `components/reference/snake-web-code/snakewebcode/activity/SimulationAnimation.py` із `NadimGhaznavi/snake-web-code`, коміт `b4a6837169950cd3940ba53231298ce6033b75a5` (24 жовтня 2026 року). Його предметна візуалізація, індексовані вручну кольори, 75-мілісекундний інтервал і GIF-байти у відповіді демонструють реальні вимоги. Це **не** універсальна реалізація, і її не можна імпортувати чи переносити в предметну область іншого застосунку.
- **Перевірка:** `tests/test_gif_animation.py` перевіряє цикли кодування, тривалості, повторення, палітри, прозорість, незмінність джерела й недійсні запити.
- **Необов’язкова навичка Codex:** `bmforge-gif-animation`, яка встановлюється через наявне закріплене добровільне налаштування компонентів. Вона пакує специфікацію, шаблон і локальний незмінний приклад; встановлення не створює застосунку для генерації GIF.

## Критерії приймання

1. Закодуйте щонайменше два різні повнорозмірні кадри; відкрийте GIF знову й перевірте порядок, кольори, розміри, правила повторення й відновлення/видалення кадрів.
2. Перевірте збережені затримки, що не кратні 10 мс (наприклад 75 мс), накопичувальне округлення без довготривалого дрейфу та явну паузу останнього кадру.
3. Перевірте збереження значень палітри `P` та незалежність результату від подальшої зміни вихідного зображення.
4. Перевірте накладання прозорих джерел на налаштований фон замість покладання на невизначену альфа-семантику GIF.
5. Відхиляйте порожні послідовності, неправильні розміри чи фон, кадри іншого розміру й недійсні тривалості без створення артефакту успіху.
6. Перевірте і байтовий GIF, і файловий результат; правила публікації та збереження належать застосунку.
7. Переконайтеся, що імпортуються лише схвалені модулі; реалізація містить `BMFORGE_COMPONENT` з ID `bmforge.gif-animation` та версією `0.1.0` і не імпортує модулів BMForge чи Snake Web.
8. Установіть лише вибрану навичку `bmforge-gif-animation` у тимчасовий проєкт разом із локальними специфікацією, шаблоном та еталоном; оновлення потребують схвалення, а автоматична перевірка лише сповіщає.
