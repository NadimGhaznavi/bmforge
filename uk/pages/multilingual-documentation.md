**Ця сторінка стосується статичної документації Jekyll, а не локалізації застосунків під час виконання.** Для повідомлень інтерфейсу й CLI нових застосунків дивіться [Локалізацію застосунків]({{ site.baseurl }}{% link uk/pages/component-localization.md %}), що передбачає стабільні ключі та англійський вихідний каталог із першого випуску.

Перекладайте документацію лише після завершення проєкту, коли інтерфейс і вміст усталилися. Під час розробки готуйте англійські метадані й конфігурацію відповідно до [Налаштування Jekyll]({{ site.baseurl }}{% link uk/pages/jekyll-setup.md %}). Це дозволяє не підтримувати переклади під час активних змін.

## Організація перекладів

Тема забезпечує перемикач мов і вибір за мовою браузера. Зберігайте цю поведінку в спільній темі: окремі JavaScript-файли, копії макетів теми чи плагіни перекладу для документації не потрібні. Саме увімкнення налаштування не перекладає вміст: кожен переклад має бути окремим Markdown-файлом.

Дотримуйтеся структури каталогів блогу: англійська в корені, переклади в каталогах мов. Для української використовуйте `uk/index.md` як перекладену головну сторінку та `uk/pages/` для посібників. Повторно використовуйте зображення з `pages/images/`, якщо саме зображення не потребує перекладу. Інші мови розміщуйте у власних каталогах.

## Відповідність сторінок

Для кожної сторінки, включно з головною:

- Установіть `lang` за мовою вмісту, наприклад `en` або `uk`.
- Установіть `locale` для тексту інтерфейсу теми, наприклад `en-US` або `uk`.
- Установіть `language_name` як видиму назву, наприклад `English` або `Українська`.
- Надайте всім перекладам тієї самої сторінки однаковий стабільний `translation_key`. Для різних сторінок потрібні різні ключі, а для кожної пари ключа й мови — лише один файл.
- Призначте кожному перекладу власну URL-адресу. Англійську адресу залишайте незмінною, а перекладені URL починайте з коду мови.

Наприклад, початок англійського посібника `pages/guide.md`:

```yaml
---
title: "Project Guide"
lang: en
locale: en-US
language_name: English
translation_key: __PROJECT_SLUG__-guide
permalink: /pages/guide/
---
```

Його український відповідник у `uk/pages/guide.md`:

```yaml
---
title: "Посібник проєкту"
lang: uk
locale: uk
language_name: Українська
translation_key: __PROJECT_SLUG__-guide
permalink: /uk/pages/guide/
---
```

## Переклад головної сторінки й навігації

Для `uk/index.md` використовуйте `translation_key` англійської головної сторінки, українські мовні метадані, `layout: single` і `permalink: /uk/`. Перекладіть огляд і навігацію. Використовуйте `layout: single` для головних сторінок документації; окремий макет списку перекладених дописів належить лише блогу.

{% raw %}
Перекладені посібники повинні вести до головної сторінки своєю мовою, наприклад `[Головна документації]({{ site.baseurl }}{% link uk/index.md %})`. За наявності перекладу посилайтеся саме на нього. Якщо сторінка існує лише англійською, використовуйте посилання з позначкою англійської мови. Не перекладайте команди, ідентифікатори коду, ключі конфігурації чи шляхи спільних ресурсів.

## Підтримка опублікованих перекладів

Після публікації підтримуйте переклади відповідно до змін оригіналу. Для кожної перекладеної сторінки повинна існувати англійська версія як стандартний варіант. Перемикач показує лише наявні переклади поточної сторінки; окремий реєстр мов не потрібен.

## Перевірка перекладів

- Перевірте метадані мови, унікальність пари `(translation_key, lang)` і окрему URL-адресу.
- Перевірте наявність англійського відповідника кожної сторінки й доступність із мовної головної сторінки.
- Після публікації перевірте перемикач мов, прямі посилання, локалізовану навігацію й вибір за мовою браузера. Ручний вибір використовує параметр URL `mm_lang`; автоматичне визначення перевіряйте без нього. Для невідомої мови браузера має використовуватися англійська.
