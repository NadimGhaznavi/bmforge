Створюйте документаційний сайт нового проєкту на GitHub Pages зі спільною темою `NadimGhaznavi/minimal-mistakes`. Цей процес готує конфігурацію Jekyll та англомовні файли документації за прикладами BMGeoIP і BMDynIP.

Записуйте особливі вимоги чи винятки налаштування у власній документації проєкту.

Визначте назву нового проєкту за [Відповідністю CMDB]({{ site.baseurl }}{% link pages/cmdb-compliance.md %}), щоб назва репозиторію, пакета й параметри випуску були узгоджені.

## Налаштування сайту

Скопіюйте [шаблон конфігурації]({{ '/templates/_config.yml' | relative_url }}) до `_config.yml` в корені нового проєкту. Замініть кожне `__PLACEHOLDER__` такими значеннями:

| Заповнювач | Значення |
| --- | --- |
| `__PROJECT_SLUG__` | Назва репозиторію, наприклад `bmforge`; також ідентифікатор сайту MyCount |
| `__PROJECT_TITLE__` | Читабельна назва проєкту |
| `__PROJECT_DESCRIPTION__` | Одне речення про призначення проєкту |
| `__GITHUB_OWNER__` | Власник репозиторію чи організація з віддаленого Git |
| `__SITE_HOST__` | Опублікована назва хоста без протоколу та шляху |
| `__SITE_BASEURL__` | Порожній рядок для власного домену; `/repository-name` для URL проєкту GitHub Pages |
| `__PROJECT_LOGO__` | Шлях до наявного логотипу в `/pages/images/` або порожній рядок |
| `__AUTHOR_NAME__` | Публічне ім’я власника проєкту |
| `__AUTHOR_LOCATION__`, `__AUTHOR_EMAIL__` | Публічні відомості про автора; порожні рядки для пропущених |
| `__AUTHOR_WEBSITE__` | URL сайту автора; видаліть відповідне посилання, якщо не використовується |
| `__START_YEAR__` | Рік початку проєкту |

Значення репозиторію отримуйте з віддаленого Git, а назву й опис — із короткого опису проєкту. Використовуйте вже визначені дані власника й назву хоста; відсутні значення отримайте від власника. BMGeoIP і BMDynIP використовують `<project-slug>.osoyalce.com` із порожнім `baseurl`.

Збережіть спільні стандартні налаштування:

- Віддалену тему `NadimGhaznavi/minimal-mistakes` зі стилем `dark`.
- Точку MyCount `https://count.osoyalce.com/count`.
- Увімкнену багатомовність із `en` як мовою за замовчуванням і `en-US` як стандартною локаллю.
- Kramdown/GFM Markdown і підсвічування Rouge.
- Сторінки документації з `layout: single` та панеллю автора; шаблон також встановлює `classes: wide`.
- Список плагінів і параметри Markdown із шаблону.

Спільна тема відповідає за оформлення. Додавайте локальні макети, CSS або JavaScript лише за конкретної вимоги проєкту.

## Створення кореня документації

У корені проєкту створіть структуру:

```text
_config.yml
index.md
README.md
pages/
  images/
```

Використовуйте `index.md` як єдину вхідну сторінку документації. Додайте YAML-метадані з назвою проєкту:

```yaml
---
title: "Project Name"
layout: single
author_profile: true
lang: en
locale: en-US
language_name: English
translation_key: __PROJECT_SLUG__-home
permalink: /
---
```

Після метаданих розмістіть логотип, якщо є, короткий огляд проєкту й посилання на наявну документацію. `README.md` має містити лише короткий огляд і посилання на сайт.

Розміщуйте англомовну документацію в `pages/`, а спільні зображення — в `pages/images/`. Кожна сторінка документації повинна мати YAML-метадані `title`, `lang: en`, `locale: en-US`, `language_name: English` і власний стабільний `translation_key`. Кожна англомовна сторінка має бути доступна з `index.md`.

## Підготовка багатомовності

Зберігайте цей блок в `_config.yml` кожного нового проєкту:

```yaml
multilingual:
  enabled: true
  default_lang: en
```

Під час налаштування додавайте англійські мовні метадані й стабільні ключі перекладу. Створюйте справжні переклади лише після завершення проєкту, коли інтерфейс і документація стали стабільними. На цьому етапі дотримуйтеся [Багатомовної документації]({{ site.baseurl }}{% link uk/pages/multilingual-documentation.md %}).

## Перевірка файлів сайту

- Переконайтеся, що всі заповнювачі конфігурації замінені, а назва проєкту, репозиторій, хост, логотип і ідентифікатор MyCount узгоджені.
- Перевірте YAML-метадані, англійські мовні атрибути, унікальні ключі перекладу, внутрішні посилання, шляхи зображень і навігацію з `index.md`.

## Публікація сайту

Дотримуйтеся [Публікації на GitHub Pages]({{ site.baseurl }}{% link uk/pages/github-pages-publishing.md %}), щоб налаштувати workflow, домен і HTTPS, а потім перевірити опублікований сайт.
